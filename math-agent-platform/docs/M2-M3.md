# M2 and M3 mathematics interfaces

M2/M3 extend the independent Python engine and generated desktop catalogue with
`equation_math`, `matrix_math`, `calculus_math`, and `convex_model`. Existing tools
remain available. `numeric_math` adds `roots` and `system_root`; matrix-form
`convex_optimize` adds numerical KKT diagnostics and rational-verified LP witnesses.

These are bounded interfaces with explicit unresolved/unsupported outcomes. They
do not provide a general decision procedure for all equations, domains, improper
integrals or optimization certificates. The combined regression phase is deferred;
new regression cases are in `engines/mathematics/tests/test_m23.py`.

## Equation solving

All equation inputs are real, use the shared parser, and retain original-domain
conditions before simplification. Declare every variable and parameter.

| Operation | Supported scope | Result |
| --- | --- | --- |
| single | One equation, one unknown, no parameters | Solution set, original-equation substitution, rejected/conditional candidates |
| linear_system | Exact linear systems; at most one real rational-function parameter and 3 rows/unknowns for parameter branching | Unique, parametric, empty or undefined branches |
| polynomial_system | QQ polynomials, at most 3 unknowns, structural degree 4 | Finite real solutions when representable; positive-dimensional/unresolved otherwise |
| inequalities | One real variable, explicit left/relation/right records | Exact set where supported; unresolved otherwise |

Parameter branching examines augmented-matrix minors. Generic and exceptional
parameter values are kept separately; extra branches can be redundant but are not
omitted merely because a sample agrees with the generic solution. Coefficient and
minor degree is limited to 8, with at most 24 exceptional real values. Original
domain conditions remain additional restrictions on every branch.

Finite candidates are checked against original expressions and conditions. A
failed substitution is excluded; an undecided substitution remains conditional.
Completeness is distinct from candidate validity. General `solveset` conclusions
are marked solver-reported. Positive-dimensional polynomial systems do not become
empty solution sets.

## Exact and numerical matrices

`matrix_math` supports the following:

- Exact determinant, rank, inverse, nullspace, linear solution space, and symmetric
  quadratic-form inertia. Inputs are real algebraic constants represented by
  strings or integers, at most 12 by 12. JSON floating-point entries are rejected.
- Numerical economic QR, SVD, least squares and square linear solve, at most
  100 by 100. Results include reconstruction/residual checks, condition number and
  singular values where applicable. `rankTolerance` controls numerical rank for
  solve/least_squares; null means the backend default, which is reported.
- Sparse square systems up to 2000 by 2000 and 20000 COO entries, solved by GMRES.
  The matrix is never densified for condition estimation. Missing condition
  information is explicit; iteration-limit results remain partial.

Exact solutions are verified by matrix identities. Numerical rank deficiency
returns a minimum-norm candidate and a warning, not a uniqueness claim. Small
backward residual does not establish small forward error for an ill-conditioned
matrix. Parameter matrices belong in `equation_math`, not the constant-matrix API.

## Multiple and multivariable roots

`numeric_math.roots` selects exact QQ polynomial isolation when the original
expression has no additional domain restrictions. It preserves multiplicities,
returns rational isolating intervals, and checks the number of distinct roots in
each interval and across the requested closed interval. This route accepts
`precision.mode="certified"` or `certificationRequired=true`; interval endpoints
are the received numeric bounds interpreted by their decimal representation.

The generic route samples a finite grid and applies bracketed root finding. It
returns candidates and unresolved intervals, always with partial completeness.
Even a searched bracket is not independently certified continuous or unique, and
even-multiplicity roots can be missed. Generic certification requests are rejected.

`system_root` uses a declared variable order, equally sized expressions and an
initial guess. It returns one local candidate and residual/convergence diagnostics.
It does not certify uniqueness or a complete multivariable solution set.

## Multivariable differentiation

`calculus_math` implements partial derivatives (total order up to 5), gradient,
Jacobian, Hessian, and first implicit derivatives. Variable order and matrix shape
are explicit. Derivatives remain symbolic; optional `verifyAt` is a local central
finite-difference heuristic for gradient/Jacobian/Hessian.

An implicit derivative requires exactly `[independent, dependent]` variables.
The result retains both the original curve equation and the nonzero dependent
partial derivative. MathIR now includes `Relation` and `Conditioned` nodes so these
conditions survive reuse. `Conditioned.expression` cannot be used independently
of its `conditions` without weakening the stated result.

## Integration and singularities

Integration limits must follow the declared variables in **innermost-to-outermost**
order. A bound can depend only on later integration variables. Bounds are exact
strings; `inf` and `-inf` denote infinite endpoints.

Symbolic integration supports finite/improper intervals, ordered disjoint piecewise
segments, and iterated integrals. Constant interior singularities are split where
enumerable. Opposite infinities are never cancelled into a Cauchy principal value.
An unevaluated integral with an infinite endpoint is unresolved, not automatically
divergent. Conditional expressions and oscillatory accumulation bounds keep
convergence unknown. For iterated integrals, no interchange-of-order theorem or
absolute integrability is implied.

Each piecewise segment has its own domain. Gaps between supplied segments are
allowed: the operation integrates the supplied pieces, not an implicitly completed
function. Intervals on which the original real integrand is undefined on a
positive-length set are rejected when that fact can be established.

Numerical mode currently supports one-dimensional improper/piecewise integration.
It reports accumulated quadrature error **estimates**, not rigorous bounds or a
convergence theorem. Numerical multiple integration is explicitly unsupported
until total error propagation is implemented. General multivariable singularity
analysis remains conditional; partial results disclose this.

## Named convex modeling

`convex_model.solve` supports named continuous variables, explicit scalar/vector/
matrix shapes, constants and parameters, objectives, and named constraints.
There are at most 100 scalar decision variables and 100 declared constraints.

Whitelisted expression nodes are:

- `constant(value)`, `variable(name)`, `parameter(name)`.
- Binary `add`, `subtract`, `multiply`, `matmul`, `quad_form` with `args`.
- Unary `negate`, `sum`, `max`, `abs`, `sum_squares`, `norm`, `index` with `args`.
- Vector norm orders 1, 2 and `inf`; vector indexing has an explicit integer index.

Products require a constant operand. Quadratic matrices must pass the symmetric
PSD check; near-negative uncertain eigenvalues are not silently clipped. Only
scalar broadcasting is allowed. Equality and inequality shapes are checked before
CVXPY DCP canonicalization and CLARABEL solving. Unsupported/non-DCP expressions
are reported distinctly from infeasibility.

The returned objective is evaluated on the original expression graph and includes
constant terms and the original maximize/minimize sense. Results map variables
and duals back to original names; auxiliary solver variables are not user variables.
Every original constraint is checked with absolute plus relative tolerance in its
own units. Solver preprocessing is not an independently certified scaling policy.

## KKT checks and LP certificates

Available gradients and duals support numerical stationarity, inequality-dual
feasibility and complementarity checks. Nonsmooth atoms such as max/abs do not
receive a fabricated KKT subgradient: the missing check is reported. Primal checks,
solver status and optimality diagnostics remain separate.

Definite infeasible or unbounded matrix-form LP statuses trigger a bounded auxiliary
witness search. A candidate is rationally reconstructed and accepted only when
Fraction arithmetic verifies all required identities/inequalities:

- Farkas: nonnegative inequality multipliers, zero combined left-hand side, and
  strictly negative combined right-hand side.
- Unboundedness: a feasible point, feasible recession direction and strictly
  decreasing linear objective.

The scope is the **received decimal coefficients**. Rational reconstruction may
fail, in which case the certificate is unavailable and the original solver status
is retained. QP/SOCP and generic named-model infeasibility certificates are not yet
independently reconstructed. Numerical KKT checks are not formal optimality proofs.

## Deferred combined verification

The new Python regression file covers parameter specializations, excluded roots,
finite versus positive-dimensional systems, exact matrix identities, numerical
decompositions, sparse solving, multiple roots, derivative shapes/conditions,
piecewise domains, convergence semantics, original optimization objectives and LP
certificates. Existing catalogue and certificate expectations have been updated.

Final verification should run Python engine tests, generated-contract consistency,
TypeScript checks, desktop build, and the relevant desktop regressions together.
Syntax/type checks and selected manual smoke calls are not a substitute for that
deferred regression run.
